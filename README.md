# 這堂課值得上嗎

> **線上版 → https://fansia.github.io/course-check/**（English → `/course-check/en/`）

看到一堂線上課心動，但銷售頁只會講好話、評價牆全是廠商自己挑的。

這是一頁式工具：填四格（課程網址、你的背景、想解決的問題、預算），一鍵把「課程盡職調查」的 prompt 送進 ChatGPT、Gemini、Claude 或 Perplexity，用它們的免費額度去 PTT、Dcard、Threads、方格子、YouTube 留言翻真實心得，順便把講師的底細查一遍，最後給出買／不買的明確結論。

另有一版專給 **Meta AI** 的 prompt，專門撈 Threads、IG、FB 上那些外部爬蟲抓不到的零散評價。

頁面本身就是產品頁：上面是工具，下面是說明與常見問題。中文在 `index.html`、英文在 `en/index.html`（介面是英文，送給 AI 的 prompt 維持中文，因為要搜的是台灣社群）。沒有建置流程、沒有相依套件。

## Prompt 在做什麼

**六個步驟**

1. **讀官方頁面** — 定價、是否買斷、退費政策、單元數、最後更新，以及有沒有單元還標著「製作中」（你買的是期貨）。
2. **去第三方場域找真實聲音** — PTT、Dcard、Threads、FB 公開社團、方格子、部落格、YouTube 留言。正評向與負評向的關鍵字都要搜。
3. **查講師本人** — 課程品質的上游是講師，而銷售頁的自我介紹是他自己寫的。
4. **分級證據** — 每一則引用都要標可信度。
5. **挖出被修飾過的摩擦訊號** — 就算在廠商自己的證言裡也常藏著真話。
6. **找替代方案的機會成本** — 免費資源夠不夠用。

### 證據分級 A/B/C/D

AI 上網查評價最常見的失敗，是抓到廠商官網那面「100+ 則學員好評」的牆，就下結論說口碑很好。所以 prompt 強制它替每一則引用標上來源等級：

| 等級 | 來源 | 怎麼看待 |
|---|---|---|
| **A** | 第三方獨立長文心得 | 可信度最高 |
| **B** | 論壇與社群零散討論 | 看趨勢，不看單則 |
| **C** | 帶折扣碼或聯盟連結的推薦文 | 當廣告看 |
| **D** | 廠商官網的學員見證 | **不得作為口碑證據** |

### 講師背景查核

輸出要分成兩欄：**可交叉驗證的事實** vs. **只有他自己說、找不到佐證的宣稱**。最後回答一句話——他是這個領域的實作者，還是主要在教這個領域？

- 他自己做出過什麼（經營中的公司、產品、作品集、GitHub、第三方媒體報導）
- 實作年資 vs. 開課時間（剛學會就開課是紅旗）
- 銷售頁的數字能不能交叉驗證（學員人數、營收、合作品牌、得獎紀錄）
- 過往課程爭議、退費糾紛、內容抄襲、誇大宣傳
- 免費內容的品質（那通常就是付費內容的下限）
- 他現在還在做這件事，還是主要收入已經來自賣課

### 誠實規範

這是整段 prompt 最重要的部分：

- 不准編造評價或連結，每則引用附真實網址。
- **找不到負評就直說找不到，並解釋原因**（課太新、社群在 Discord／LINE 私域、討論量本來就低）。不准用「整體評價正面」填補資料空白——**沒有負評不等於口碑好**。
- 區分「查證到的事實」與「推論」。
- 官網沒公開價格就說沒公開，不要猜一個數字當事實。

### 九個紅旗

逐項標示 ✅ 沒問題／⚠️ 要留意／🚩 高風險：飢餓行銷與倒數計時、無退費政策、承諾收入或效果、只有廠商自營證言、課程尚未完成卻已開賣、社群封閉查不到真實回饋、講師無可查證的實作成果、講師經歷無法交叉驗證、內容可被免費資源取代。

## Threads 版：撈外部爬不到的那一半

Threads 上其實有評價，只是外部搜尋引擎抓不到。ChatGPT、Gemini 去搜 `site:threads.com` 經常空手而回，而真話往往不在主貼文，是在留言串裡。

所以多了第三種 prompt，配 **Meta AI** 用——它讀得到自家平台的貼文與留言。這一輪**不下買／不買的結論**，只負責把清單撈出來，跑完再貼回完整版的報告當 B 級證據。

它跟另外兩版的差別：

- 搜 Threads、IG、FB 公開社團，**貼文和留言串都要搜**。
- 每一則標三件事：**連結、帳號性質、日期**。拿不出連結的不准混進清單。
- 帳號性質分四類：一般使用者／講師本人或團隊／帶折扣碼的業配／只發過這一篇的新帳號。
- 特別挖「被已讀不回的提問」（有人問退費、問更新進度然後沒有回應）和「買了放著沒看」這類自嘲——最常見、也最少被當成負評的訊號。
- 檢查好評是不是集中在少數互相追蹤、或都帶同一組折扣碼的帳號。
- 明文禁止把一般網頁搜尋結果、新聞、部落格當成 Threads 貼文來報。

**已知限制**：Meta AI 給貼文連結的紀錄不穩，有時內容講得出來、出處卻附不上。這也是為什麼 prompt 要求「拿不出連結的不要混進清單」——沒有連結你就沒辦法自己點開查證，那就不該當證據用。

## 三種版本

| 版本 | 長度 | 搭配 | 行為 |
|---|---|---|---|
| **完整版** | 約 2,100 字 | 任一家 | 七段輸出。太長塞不進網址，按鈕會複製，開好新對話後貼上 |
| **精簡版** | 約 750 字 | ChatGPT / Claude / Perplexity | 壓到能塞進網址，會**自動帶入問題** |
| **Threads 版** | 約 1,400 字 | Meta AI | 只蒐證不下結論，走複製後貼上 |

Gemini 和 Meta AI 沒有公開的預填參數，一律走「複製後貼上」。按鈕上的小字會依當下版本自動切換提示，不會宣稱會自動帶入卻沒帶入。

## 部署

```bash
git clone https://github.com/fansia/course-check.git
cd course-check
```

丟到任何靜態主機都能跑。GitHub Pages：

```bash
gh api -X POST repos/:owner/course-check/pages \
  -f "source[branch]=main" -f "source[path]=/"
```

或在網頁上：Settings → Pages → Source 選 `main` / `root`。

## 自行修改

- **Prompt 內容**在 `index.html` 底部的 `buildFull()` 與 `buildLite()` 兩個函式裡，純字串陣列，直接改。
- **要加平台**：在 `TARGETS` 物件加一筆，`param` 填該站接收問題的 query 參數名稱，沒有就填 `null`（按鈕會自動改成「複製後貼上」）。
- **URL 長度上限**由 `URL_BUDGET` 控制（預設 7000，指的是 encode 後的長度）。超過就不做預填，改走剪貼簿。
- **配色**：沿用 Eric 個人網站的樣式（設計參考 [Kami](https://kami.tw93.fun)，中文字體霞鶩文楷 TC）。token 全部在 `:root`，深色主題在 `@media (prefers-color-scheme:dark)` 與 `:root[data-theme="dark"]` 各覆寫一次。右上角是月亮／太陽切換，選擇會記住。
- **中英文要一起改**：改了 `index.html` 的文案或工具，`en/index.html` 也要同步；兩頁的 prompt 產生邏輯必須完全一樣。
- 填過的內容存在 `localStorage`，下次開還在。

## 已知限制

- 各家 AI 的預填參數（`?q=`）是慣例而非公開 API，平台改版就可能失效。所以**每個按鈕都一定會先複製到剪貼簿**，預填只是加分項，失效了也不影響使用。
- AI 產出的調查結果仍需自行查證，引用連結請點開確認。
